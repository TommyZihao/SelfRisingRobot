# ATOM S3R 起身机器人 V3.1

此目录独立保存已在真机使用的 S3R 版本，基于本项目原有两舵机结构。V3.1 与 V3 使用同一最优策略，仅修改固件为持续控制。原项目其它目录不变。

## 接线与运动范围

- **GPIO1：下部、靠近底板的舵机，±90°。** XML 中为 `servo1_joint`，策略动作第 0 项。
- **GPIO2：上部舵机，±120°。** XML 中为 `servo2_joint`，策略动作第 1 项。
- 舵机与控制器共地，舵机使用合适的供电；不要按其它旧版本中的上下命名交换通道。

XML 已加入 8 g S3R、两个约 10 g 舵机及 25 g 电池。电池 40×30×10 mm，在底板上与 S3R 中心相距 45 mm；总名义质量 103.694 g。外形和重心位置仍含照片估计，摩擦和舵机动态也未实测标定。

## 固件行为

固件在 `firmware/robo03_atom_s3r_zihao_v3/`，目录名保留 v3，实际版本字符串为 **V3.1**。

1. 自动模式持续约 50 Hz 运行策略，无 43°门槛和 300 ms 等待。
2. 起身完成后继续运行，`DONE` 只表示显示状态，不再自动硬切回零位。
3. 暂停、网页 Stop/Auto Off 保持当前目标；恢复时不清零。
4. 显式手动角度控制会关闭自动模式，并同步记录目标角度。
5. Wi-Fi 热点为 `SelfRisingRobot`（无密码），网页地址 `http://192.168.42.1`。

PWM 使用微秒输出，默认中心 1500 μs、半跨度 1000 μs。上下舵机分别把 ±90°、±120°映射到这段脉宽。**真实角度与 PWM 的关系尚未标定**，换舵机或机械装配后应检查中位、方向和行程。

## 文件和使用方法

- `simulation/robo_s3r.xml`：MuJoCo MJCF，不是 URDF；`assets/` 含所需网格。
- `models/robo_s3r_v3.zip`：最优 PPO 权重。
- `firmware/.../policy_network.h`：导出的 4→64→64→2 actor。
- `evaluation/`：训练 loss、阶段评估、逐回合测试、统计及图片。
- `manifest.json`：模型、头文件、XML 哈希及接口记录。
- `AGENTS.md`：给 AI/自动化开发者的约束。

环境安装、仿真播放、无界面测试和 Arduino 编译烧录的完整命令见 [英文 README](README.md)。macOS 图形播放使用 `mjpython`。例如安装依赖后，在仓库根目录运行：

```sh
zihao_s3r/.venv/bin/mjpython zihao_s3r/simulation/play_policy.py --pose pitch_pos
```

输入仍是 `[roll, pitch, 下部目标角度, 上部目标角度]`，单位弧度，**后两项不是舵机实际角度**。每 20 ms 输出两个增量，最大各 ±0.08 rad，最后按上下独立范围限幅。

## 训练结果

共完成 20 次训练。比较了 PPO、A2C、完全从零、示教初始化、V2.1 继续训练、姿态扩展及物理随机性。胜出的是 **从零探索的 PPO + 多样倒地姿态 + 物理随机性**，种子 11；训练到约 200 万步，从其中约 180 万步的检查点选出模型。

在未参与调参的 2,000 次仿真测试中，V3 为 **1968/2000（98.4%）**，相同新模型和动作范围下的 V2.1 为 **1701/2000（85.05%）**。四方向分层分别为 99.2%、95.4%、99.6%、99.4%。更宽角度的额外测试为 298/300。

这不是“任何情况下都能起身”的保证，也不是实测真机成功率。用户反馈真机效果很好；仍需关注 `roll_neg` 失败状态、实际地面摩擦和舵机响应。详见 [训练与评估说明](docs/TRAINING.md)。
